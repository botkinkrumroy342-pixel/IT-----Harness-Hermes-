# IT爱学堂-慕课体系课-【Harness&amp;Hermes】多智能体开发特训营
获课：aixuetang.xyz/23627/

协作与进化——多智能体系统的两种核心能力
定位清楚之后，特训营的第二阶段进入技术核心：Harness 如何编排多智能体协作，Hermes 如何实现自我进化。这两种能力决定了多智能体系统能不能“把事做完”且“越做越好”。

Harness 的编排机制：Agent Loop 与任务状态机
Harness 最稳定的内核是 Agent Loop。它不要求模型一次性给出完整答案，而是允许模型根据当前目标和环境反馈，重复执行“判断—行动—观察—再判断”，直到任务被验证完成、进入等待、失败或取消。这个循环的关键不是循环本身，而是门控——失败的步骤不会无条件继续，而是等待人工或 Agent 自我修复。

DeepSeek Harness 的设计思路提供了另一个视角：一款“一切皆插件”的开源 Agent 执行框架，聚焦长任务可靠运行，通过可替换的 Loop 机制、按需暴露的工具 Schema、动态管理的上下文、事件驱动的持久状态、分层权限控制及多维验证体系，解决任务中断、约束丢失、上下文污染与验收失真等核心痛点。特训营中会引导学员对比不同 Harness 实现的设计取舍，建立自己的技术判断框架。

Hermes 的五种多 Agent 协作机制
Hermes 的多 Agent 能力不是单一抽象，而是五种运行时机制，按作用域和触发方式分层。delegate_task 是会话内最常用的委派入口，最多支持 3 路并行，但有三条写死在代码里的硬限制：最大深度为 2、并发子代理不超过 3 个、子代理工具集只收窄不放大。Kanban 是唯一真正跨进程的编排层，由 dispatcher 每 60 秒轮询、spawn 独立子进程执行，状态落在 SQLite，支持跨重启不丢、多 Profile 分工的长任务。

这套设计的核心取舍是：子 Agent 之间完全不通信、默认扁平不嵌套，代价是缺乏灵活的信息交换，收益是故障边界清晰。特训营中会让学员在真实项目中体会这个取舍——什么时候用轻量级的会话内委派，什么时候必须上 Kanban 的持久化编排。

自进化的快慢双循环
Hermes 的自我改进由两个循环组成。快循环不改动模型，只改动文本，包含四个闭环学习机制：定期自省触发回顾、自主技能创建、技能自改进、按需检索历史对话。慢循环则通过 RL 训练从更深层次改变模型能力。实际使用中，用 /learn 命令可以把一个完整的工作流蒸馏成可复用的技能文档，下次遇到类似任务时 Agent 自动加载并执行。

特训营在协作与进化阶段会安排一个贯穿项目，让学员同时使用 Harness 的编排能力和 Hermes 的进化能力，完成一个从需求分解到多角色执行再到经验沉淀的完整闭环。
